# Release notes — single source of truth

Every user-facing release note lives here as **one file per version**:
`release-notes/v<MAJOR.MINOR.PATCH>.md` (pre-releases: `v0.7.0-beta.md`).

Everything else is generated from these files — never edit the derived outputs by hand:

| Output | Where | Generated by |
|---|---|---|
| GitHub Release body (private `ZentroIDE/Zentro`) | release CI | `release-notes.mjs render <version>` |
| GitHub Release body (public `Zentro` repo)   | release CI | `release-notes.mjs render <version>` |
| `RELEASE_NOTES.md` (repo root, legacy path)      | postbump hook | `release-notes.mjs sync-legacy` |
| `release-notes/index.json`                       | release CI + postbump | `release-notes.mjs build-index` |
| Docs site changelog (`zentro-docs`)             | docs build | fetches `index.json` from the public repo |

`zentro/CHANGELOG.md` is **not** part of this — it stays the auto-generated internal
commit log produced by `commit-and-tag-version`. Release notes are the public story.

## File format

```markdown
---
version: 0.6.0
date: 2026-09-09          # YYYY-MM-DD, the release date
channel: stable           # stable | beta
highlights: One-line summary shown under the version heading
---

### Breaking Changes      # omit the section if there are none

- ...

### New Features

- **Bolded lead-in** — what the user gets

### Fixes & Polish

- ...
```

Supported inline markup in the body: `**bold**`, `` `code` ``, `[text](url)`. Keep it to
`###` section headings and `-` bullets — no nested lists, images, or tables.

## Workflow

1. While prepping a release, write `release-notes/v<next>.md` (or scaffold it:
   `npm run release-notes -- new 0.7.0`).
2. `npm run release` — the `postbump` hook runs `release-notes.mjs release-sync`, which
   **aborts the release** if the new version has no notes file (or it's still a stub),
   then regenerates `RELEASE_NOTES.md` and `release-notes/index.json`.
3. Push the tag. Release CI validates again (`release-notes.mjs check`), renders the
   GitHub Release bodies, and mirrors `release-notes/` + `index.json` into the public repo.

## Commands

```
npm run release-notes -- render <version> [--heading]   # print one version's notes
npm run release-notes -- build-index                     # (re)write index.json
npm run release-notes -- sync-legacy                     # (re)write RELEASE_NOTES.md
npm run release-notes -- check [--version <v>]           # CI gate; defaults to package.json
npm run release-notes -- new <version>                   # scaffold a stub file
```
